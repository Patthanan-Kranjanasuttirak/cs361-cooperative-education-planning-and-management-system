# Cooperative Education Planning & Management System

เว็บไซต์จัดการแผนสหกิจศึกษา สำหรับสาขาวิทยาการคอมพิวเตอร์ มหาวิทยาลัยธรรมศาสตร์ พัฒนาขึ้นในรายวิชา CS361 เพื่อรวบรวมข้อมูล การสมัคร การพิจารณา และการติดตามผลไว้ในระบบเดียว

[เข้าใช้งานเว็บไซต์](https://main.d2hk33ncom62gs.amplifyapp.com/login)

## ภาพรวมเว็บไซต์

เว็บไซต์แบ่งเป็นสองส่วน:

- **ส่วนสาธารณะ:** ข้อมูลสหกิจศึกษา คู่มือนักศึกษา และรายละเอียดสถานประกอบการ
- **ส่วนผู้ใช้งาน:** จัดการข้อมูลและดำเนินงานตามบทบาทหลังเข้าสู่ระบบ

## ผู้ใช้งานและความสามารถ

| บทบาท | การใช้งาน |
|---|---|
| นักศึกษา | กรอกข้อมูลและแนบเอกสาร สมัครเข้าแผนสหกิจ สมัครตำแหน่งงาน ติดตามผล และยืนยันสิทธิ์ |
| เจ้าหน้าที่ | ตรวจข้อมูล คัดกรองนักศึกษา ประกาศผล และจัดการผู้ใช้ สถานประกอบการ และภาคการศึกษา |
| กรรมการสหกิจศึกษา | ตรวจข้อมูลและผลคัดกรอง เพื่อพิจารณาคัดเลือกนักศึกษาเข้าแผน |
| ผู้ประสานงานสถานประกอบการ | จัดการข้อมูลบริษัท ตำแหน่งงาน และพิจารณาผู้สมัคร |

## ขั้นตอนการใช้งาน

1. นักศึกษากรอกข้อมูลส่วนตัว คุณสมบัติ และเอกสารประกอบเพื่อสมัครเข้าแผนสหกิจ
2. เจ้าหน้าที่ตรวจสอบและคัดกรองข้อมูล พร้อมส่งหมายเหตุภายในให้กรรมการ
3. กรรมการพิจารณาคัดเลือกนักศึกษาเข้าแผน
4. เจ้าหน้าที่ประกาศผลให้นักศึกษาทราบ
5. นักศึกษาที่ผ่านการคัดเลือกสมัครตำแหน่งงานกับสถานประกอบการ
6. สถานประกอบการพิจารณาผู้สมัคร และนักศึกษายืนยันสิทธิ์เมื่อได้รับการตอบรับ

นักศึกษาเห็นผลการคัดเลือกเข้าแผนหลังประกาศแล้ว โดยไม่เห็นหมายเหตุภายในของเจ้าหน้าที่และกรรมการ

## สถาปัตยกรรมระบบ

<img width="1382" height="702" alt="image" src="https://github.com/user-attachments/assets/7d7f66cd-5037-482a-935c-38c7174cd05f" />


- **Frontend:** แสดงข้อมูลและหน้าการทำงานตามบทบาท
- **Authentication:** Cognito จัดการการเข้าสู่ระบบและออก Token โดยเชื่อมกับ TU API และ Google ตามประเภทบัญชี
- **Backend:** ตรวจสิทธิ์ ประมวลผลเงื่อนไข และจัดการข้อมูลผ่าน API
- **Database:** เก็บข้อมูลผู้ใช้ สถานประกอบการ ตำแหน่งงาน และการสมัคร
- **File Storage:** เก็บเอกสารและรูปภาพใน S3 โดยเข้าถึงผ่าน Backend ที่ตรวจสิทธิ์
- **Monitoring:** เก็บบันทึกการทำงานและข้อผิดพลาดผ่าน CloudWatch

## การเข้าสู่ระบบและสิทธิ์เข้าถึง

ผู้ใช้เลือกบทบาทและเข้าสู่ระบบด้วยวิธีที่รองรับสำหรับบัญชีนั้น นักศึกษาใช้บัญชีมหาวิทยาลัย ส่วนผู้ประสานงานสถานประกอบการรองรับ Google Sign-in

บัญชีกรรมการ เจ้าหน้าที่ และผู้ประสานงานบางบัญชีในเวอร์ชันทดสอบใช้ mock authentication และต้องลงทะเบียนในระบบก่อน

Backend ตรวจบทบาทและสิทธิ์ของผู้ใช้ก่อนอ่านหรือแก้ไขข้อมูล การเลือกบทบาทบนหน้าเว็บเพียงอย่างเดียวไม่ทำให้ได้รับสิทธิ์เพิ่มเติม
